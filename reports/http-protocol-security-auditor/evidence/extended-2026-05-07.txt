=== HPS-EXT-05: Malformed method via raw TCP — PASS ===
Empty method (" /admin HTTP/1.1"): 400 Bad Request
Leading space in method (" GET /admin"): 400 Bad Request
Tab in method ("GET\t/admin"): 400 Bad Request

Lowercase method "get": net/http accepts it but MuxMaster does not route to the GET handler (404)
— this is correct RFC 9110 §9.1 behaviour (methods are case-sensitive).

=== HPS-EXT-13: Absolute-form URI open redirect confirmation — FAIL (HPS-2026-0005) ===
r.URL = {Scheme:"http", Host:"evil.com", Path:"/admin/"} → Location: "http://evil.com/admin"
This is the SAME finding as HPS-2026-0005, already registered as task #145 (sev=7, BACKLOG).
See evidence in hps_2026_openredirect_test.go and the original harness for full details.

Root cause confirmed: mux.go line 931 and 945:
  target := r.URL.String()
When r.URL.Scheme="http" and r.URL.Host="evil.com" (set by net/http for proxy absolute-form URI):
  r.URL.String() = "http://evil.com" + path
  http.Redirect emits Location: http://evil.com/admin

Confirmed vector: net/http DOES set r.URL.Host when server receives absolute-form URI
  from a proxy or direct HTTP/1.1 CONNECT-style client:
  GET http://evil.com/admin/ HTTP/1.1 → r.URL.Host = "evil.com" (confirmed by proxycheck.go)

Fix: replace r.URL.String() with:
  (&url.URL{Path: newPath, RawQuery: r.URL.RawQuery}).String()

=== HPS-EXT-15: SetHeader Vary preservation — PASS ===
