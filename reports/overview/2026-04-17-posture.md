## Section 2 — Critical findings in detail

### MM-2026-0001 — Tree corruption via wildcard shadow

**Technical description:** When a route with a parameter (`/a/:x`) is registered and subsequently a sibling static route (`/a/b`) is also registered, `addRoute` accepts the registration but leaves the tree inconsistent. Node split produces `wildChild=true` + `nType=static`. The `switch n.nType` in getValue does not cover this combination → `default: panic("muxmaster: invalid node type")`. Also triggerable via `/:0` + `/0`.

**Exploitability:**
- **Remote:** yes — any request touching the corrupt node panics (without `PanicHandler`, stdlib returns 500 + closes connection).
- **Pre-auth:** yes — dispatch happens before middleware.
- **Required conditions:** developer registers an ambiguous pair. Easy to introduce in large sprints with multiple collaborators; developers migrating from chi/bunrouter (which handle this case) assume the same behavior.
- **Blast radius:** the corrupt node impacts all sub-paths. `/a/b` returns 404 silently (instead of the static handler) → **latent auth bypass** if the developer assumes the protected route is active.

**Recommended fix (diff sketch):**
```go
// tree.go:122-127 — before adding static child, reject wildChild sibling
if c != ':' && c != '*' && c != '{' {
    if n.wildChild {
        panic("muxmaster: static segment '" + string(c) +
              "' in path '" + fullPath +
              "' conflicts with existing wildcard sibling")
    }
    n.indices += string(c)
    child := &node{}
    // ...
}
```

**Blast radius:** Critical — tree is shared structure post-registration; one registration corrupts all subsequent requests.

### MM-2026-0002 — UTF-8 invariant violation

**Technical description:** `addRoute` does not validate UTF-8. Registering `/\xff` (or another byte ≥ 0x80 non-UTF-8) is accepted without panic, but silently corrupts `n.indices` vs `n.children`. Subsequent `addRoute` panics in `incrementChildPrio:160` with `index out of range [2] with length 2`; subsequent dispatch panics in `getValue:305` with `slice bounds out of range [:3] with capacity 2`.

**Exploitability:**
- **Remote:** via **config-file injection**. If the application loads patterns from YAML/env/k8s ConfigMap without validation, an attacker who can influence that source causes panic in `main()` → crashloop.
- **Pre-auth:** N/A (it is config-time).
- **Required conditions:** application loads patterns from external unvalidated source.

**Recommended fix:**
```go
// tree.go (start of addRoute/insertChild)
if !utf8.ValidString(path) {
    panic("muxmaster: route pattern is not valid UTF-8: " + strconv.Quote(path))
}
```
Additionally: audit `for i, r := range path` vs `for i := range len(path)` — both are used but with different semantics (runes vs bytes).

**Blast radius:** Critical — boot-time DoS; also corrupts hot-path in dynamic scenarios.

### MM-2026-0003 — Race in unsafe.Add(r.ctx) cross-goroutine

**Technical description:** The pattern `*origCtxPtr = rc; handler.ServeHTTP(...); *origCtxPtr = origCtx` in `mux.go:464-480` and `mux.go:521-537` assumes that `*http.Request` is goroutine-owned by the dispatcher. Handlers that spawn goroutines with `r` retained (a completely legitimate pattern in Gin/Echo/chi/httprouter) produce a guaranteed race: the child goroutine can read `r.Context()` while the main goroutine writes, and `rc` may have been returned to the pool and reused by another request.

**Exploitability:**
- **Local:** race is deterministic under `-race`. Observable output with crossed values.
- **Remote:** production under load produces cross-request data leak (contamination via `rc.params` reading another request).
- **Required conditions:** handler that does `go func() { _ = r.Context() }()` (async audit log, background work). Extremely common.
- **Blast radius:** any idiomatic Go app.

**Recommended fix (architectural decision):**

- **Option A (preferred):** Replace `unsafe.Add` with `r.WithContext(rc)` — cost ~1 alloc/param-req (estimated); race architecturally eliminated.
- **Option B:** Keep `unsafe.Add` + strong normative documentation + linter rule in CI that detects `go func(){ ... r ... }()`.

Threat-modeler recommendation: **Option A**, with benchstat before/after to quantify regression (H-034 is that hypothesis). Performance still superior to non-zero-alloc competitors (chi, Gin).

**Blast radius:** Critical — silently breaks apps migrating from chi/gin/httprouter.

### MM-2026-0004 — RedirectTrailingSlash pre-middleware emission

**Technical description:** In `mux.go:491-499`, when `getValue` returns `tsr=true` and `handler=nil`, the dispatch emits `http.Redirect` directly — the middleware chain (applied via `wrapMiddleware(handler, ...)` in `Handle()`) never enters play.

**Exploitability:**
- **Pre-auth:** yes — reconnaissance without credentials.
- **Remote:** yes — public HTTP request.
- **Required conditions:** application registers `/admin/` (with trailing slash). Attacker sends `GET /admin` → 301.
- **Blast radius:** enumerates all endpoints with auth.

**Recommended fix (diff sketch):**
```go
// Option 1 — wrap dispatch fallback with middleware chain
// In Mux.New(), after middleware setup:
m.notFoundHandler = wrapMiddleware(http.HandlerFunc(m.dispatchFallback), m.middleware)

// In dispatch, instead of http.Redirect directly:
if tsr && m.RedirectTrailingSlash {
    // emit redirect via wrapped chain
    m.notFoundHandler.ServeHTTP(w, r)
    return
}
```

**Competitor comparison:** chi applies middleware before any dispatch decision; MuxMaster is the outlier.

**Blast radius:** complements MM-2026-0004 for complete reconnaissance. Composite in MM-TM-2026-0001.

### MM-2026-0006 — Logger CRLF/ANSI/NUL injection

**Technical description:** `middleware/logger.go:30` — `fmt.Fprintf(out, "... %s ...", ..., r.URL.Path, ...)`. Stdlib rejects literal CRLF in request-target (400), but **percent-decodes `%0D%0A` into `r.URL.Path`**. Logger writes raw bytes.

**Exploitability:**
- **Pre-auth:** yes (log write happens on all requests).
- **Remote:** yes.
- **Required conditions:** none.
- **Attack scenarios:**
  - **Log forgery:** CRLF injection creates false lines in CLF format; plausible deniability for real traces.
  - **ANSI clear:** `%1B%5B2J%1B%5BH` clears screen in TTY viewer → obfuscation.
  - **NUL truncation:** SIEMs truncate; hide part of the path.
  - **Right-to-left override:** spoof URLs in log viewers with bidi support.

**Recommended fix:**
```go
// middleware/logger.go
import "strconv"

func sanitiseForLog(s string) string {
    q := strconv.QuoteToASCII(s)
    return q[1 : len(q)-1]
}

// In logger.go:30:
fmt.Fprintf(out, "%s %s %s %d %s\n",
    time.Now().Format(time.RFC3339),
    sanitiseForLog(r.Method),
    sanitiseForLog(r.URL.Path),
    rec.status,
    time.Since(start),
)
```

### MM-2026-0007 — compress unbounded buffer

**Technical description:** `middleware/compress.go:25-31` — `g.buf = append(g.buf, b...)` accumulates the entire response before flush. `g.done` is only true after handler returns. Handler that writes 10GB → `g.buf` allocates 10GB (peak ~15-20GB due to `append` doubling).

**Exploitability:**
- **Pre-auth:** depends on the endpoint. If the endpoint is public + produces large responses (image download, API bulk export), attacker sends `Accept-Encoding: gzip` (default for all browsers).
- **Required conditions:** none beyond `Accept-Encoding: gzip`.

**Recommended fix (diff sketch):**
```go
// middleware/compress.go — streaming instead of buffering
type gzipResponseWriter struct {
    http.ResponseWriter
    gz       *gzip.Writer
    small    []byte // bounded buffer only for sniffing / minCompressSize
    smallMax int
    started  bool
}

func (g *gzipResponseWriter) Write(b []byte) (int, error) {
    if g.started {
        return g.gz.Write(b)
    }
    if len(g.small)+len(b) < g.smallMax {
        g.small = append(g.small, b...)
        return len(b), nil
    }
    // flush small buffer + start streaming
    g.Header().Set("Content-Encoding", "gzip")
    g.Header().Add("Vary", "Accept-Encoding")
    g.Header().Del("Content-Length")
    g.gz = acquireGzip(g.ResponseWriter)
    if len(g.small) > 0 {
        _, _ = g.gz.Write(g.small)
        g.small = nil
    }
    g.started = true
    return g.gz.Write(b)
}
```

## Section 4 — Multi-agent composites (confirmed zero-day hypotheses)

The 3 most concerning attack chains — all confirmed with evidence from multiple agents and promoted to MM-TM-NNNN.

### MM-TM-2026-0001 — Pre-auth reconnaissance + credential theft pipeline (Critical)

**Agents involved:** HPS + PRF + TSC + MSR. **Findings source:** MM-2026-0004, 0005, 0009, 0020, 0027.

**End-to-end attack (without auditing anything):**
1. Attacker sends `GET /admin` with `/admin/` registered + auth middleware → `301 Location: /admin/` (MM-2026-0004). Auth middleware **never fires**.
2. Sends `OPTIONS /secret` → `204 Allow: GET,POST,OPTIONS` (MM-2026-0005) — discovers method matrix.
3. Sends `GET /admin//console` → `301 Location: /admin/console` — discovers canonical form of protected routes.
4. Now knows that `/admin` exists and has auth. Tries `Basic auth` with `alice:wrong`, `bob:wrong`, `charlie:wrong`... Via Welch p=0 in N=1e5 samples (MM-2026-0009), discriminates valid usernames from invalid (mean diff 319-429 ns).
5. For each valid username, iterates password length 1..128 — maximal latency marks the correct length (MM-2026-0020).
6. Executes online brute-force without rate-limit (MM-2026-0027), unlimited.

**Result:** infrastructure enumerated + N authenticated users, **without** any valid credential being tested up to step 6.

**Composite severity:** Critical. It is the **differential** of this sprint compared to isolated audits — no individual agent sees this chain; it is only visible by crossing findings.

**Recommended mitigation:** fix all 5 source findings. TSR/FixedPath/OPTIONS/405 blocks must pass through the middleware chain.

---

### MM-TM-2026-0002 — Multi-channel exfiltration + audit-trail forgery (High)

**Agents involved:** HPS + MSR + DOS + TSC. **Findings source:** MM-2026-0006, 0008, 0011, 0012, 0047.

**End-to-end attack:**
1. Attacker forges "trusted proxy" IP via `X-Forwarded-For: 10.0.0.1` (MM-2026-0008). Logger records forged IP.
2. Sends single request containing exfiltration payload **replicated in 4 simultaneous channels**:
   - `r.URL.Path = /abc%0D%0A<payload>` → log line forgery (MM-2026-0006).
   - `X-Request-ID: <payload>` → reflected in response X-Request-ID header (MM-2026-0011).
   - `Origin: <payload>` → reflected in ACAO if allowAll (MM-2026-0012).
   - `?guess=<payload>` with secret in response body + compress enabled → BREACH oracle (MM-2026-0047).
3. Attacker correlates channels to accelerate exfiltration (2 or more surviving channels → confirm bit).

**Composite severity:** High. Logger CRLF also allows **forging log lines that appear to be from another IP** — audit trail is completely compromised (in incident response, attacker's real traces are indistinguishable from forged lines he himself created).

**Recommended mitigation:** fix all 4 source findings (3 non-acceptable + 1 docs-only for BREACH).

---

### MM-TM-2026-0004 — Concurrency + pool + panic composite (Critical)

**Agents involved:** CSA alone (4 findings single source consolidate cross-impacts). **Findings source:** MM-2026-0003, 0014, 0015, 0017.

**End-to-end observation (not direct exploitation):**
1. Idiomatic Go application has handler `func(w, r) { go logAsync(r.Context(), ...) ; /* sync work */ }`.
2. Under load (1000 req/s), some goroutines spawned by handlers are still alive when main dispatcher restores `*origCtxPtr = origCtx` and `releaseRC(rc)` → rc returns to pool.
3. Next request gets the same rc; assigns new `rc.params`. Old goroutine, now reading `r.Context()`, sees params from the **new** request — functional cross-request contamination (MM-2026-0003).
4. If some request's handler panics, `releaseRC` is skipped (MM-2026-0015) → rc permanently leaked. Under panic storm, heap grows 5.4 KB/req.
5. If operator reloads config at runtime and reconfigures `m.NotFound` (MM-2026-0017) → race on read path.
6. Parallel unit tests sharing a Mux → `Use()` race vs `Handle()` (MM-2026-0014) → silently registers route with partial middleware.

**Composite severity:** Critical. It is **latent** in production — not directly exploitable by an attacker, but produces correctness incidents that degrade platform confidence.

**Recommended mitigation:** fix as a set — option A (replace unsafe.Add), + defer cleanup, + lock in Use/Pre, + docs thread-safety contract.

### 7.4 Recommended breaking changes
