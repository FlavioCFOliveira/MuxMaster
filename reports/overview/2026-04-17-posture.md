## Secção 2 — Findings Críticos em detalhe

### MM-2026-0001 — Tree corruption via wildcard shadow

**Descrição técnica:** Quando uma rota com parâmetro (`/a/:x`) é registada e em seguida uma rota estática irmã (`/a/b`) é também registada, `addRoute` aceita o registo mas deixa a árvore inconsistente. Split de nó produz `wildChild=true` + `nType=static`. O `switch n.nType` em getValue não cobre esta combinação → `default: panic("muxmaster: invalid node type")`. Também disparável via `/:0` + `/0`.

**Exploitability:**
- **Remote:** sim — qualquer request que toque o nó corrupto panica (sem `PanicHandler`, stdlib devolve 500 + corta connection).
- **Pre-auth:** sim — dispatch acontece antes de middleware.
- **Required conditions:** developer regista par ambíguo. Fácil de introduzir em grandes sprints com multiple collaborators; developers que migrem de chi/bunrouter (que tratam este caso) assumem mesmo comportamento.
- **Blast radius:** o nó corrupto impacta todos os sub-paths. `/a/b` retorna 404 silencioso (em vez do static handler) → **auth bypass latente** se o developer assume que a rota protegida está activa.

**Recommended fix (diff sketch):**
```go
// tree.go:122-127 — antes de adicionar static child, rejeitar wildChild sibling
if c != ':' && c != '*' && c != '{' {
    if n.wildChild {
        panic("muxmaster: static segment '" + string(c) +
              "' in path '" + fullPath +
              "' conflicts with existing wildcard sibling")
    }
    n.indices += string(c)
    child := &node{}
    // ...
}
```

**Blast radius:** Critical — tree é estrutura partilhada pós-registration; um registo corrompe todos os requests subsequentes.

### MM-2026-0002 — UTF-8 invariant violation

**Descrição técnica:** `addRoute` não valida UTF-8. Registar `/\xff` (ou outro byte ≥ 0x80 não-UTF-8) é aceite sem panic, mas corrompe `n.indices` vs `n.children` em modo silencioso. Subsequente `addRoute` panica em `incrementChildPrio:160` com `index out of range [2] with length 2`; subsequente dispatch panica em `getValue:305` com `slice bounds out of range [:3] with capacity 2`.

**Exploitability:**
- **Remote:** via **config-file injection**. Se a aplicação carrega patterns de YAML/env/k8s ConfigMap sem validação, atacante que influencie essa fonte causa panic no `main()` → crashloop.
- **Pre-auth:** N/A (é config-time).
- **Required conditions:** aplicação carrega patterns de fonte externa não-validada.

**Recommended fix:**
```go
// tree.go (start of addRoute/insertChild)
if !utf8.ValidString(path) {
    panic("muxmaster: route pattern is not valid UTF-8: " + strconv.Quote(path))
}
```
Além disso: auditar `for i, r := range path` vs `for i := range len(path)` — ambos são usados mas com semânticas diferentes (runes vs bytes).

**Blast radius:** Critical — boot-time DoS; também corrompe hot-path em cenários dinâmicos.

### MM-2026-0003 — Race em unsafe.Add(r.ctx) cross-goroutine

**Descrição técnica:** O pattern `*origCtxPtr = rc; handler.ServeHTTP(...); *origCtxPtr = origCtx` em `mux.go:464-480` e `mux.go:521-537` assume que `*http.Request` é goroutine-owned pela dispatcher. Handlers que spawn goroutines com `r` retido (padrão completamente legítimo em Gin/Echo/chi/httprouter) produzem race garantida: a goroutine filha pode ler `r.Context()` enquanto a main goroutine escreve, e `rc` pode ter sido devolvido ao pool e reutilizado por outro request.

**Exploitability:**
- **Local:** race é determinística sob `-race`. Observáveis output com valores cruzados.
- **Remote:** produção sob load produz cross-request data leak (contamination via `rc.params` reads de outro request).
- **Required conditions:** handler que faz `go func() { _ = r.Context() }()` (async audit log, background work). Extremamente comum.
- **Blast radius:** qualquer app Go idiomática.

**Recommended fix (decisão arquitectural):**

- **Opção A (preferida):** Substituir `unsafe.Add` por `r.WithContext(rc)` — custo ~1 alloc/param-req (estimado); race arquitecturalmente eliminada.
- **Opção B:** Manter `unsafe.Add` + documentação normativa forte + linter rule no CI que detecta `go func(){ ... r ... }()`.

Recomendação do threat-modeler: **Opção A**, com benchstat antes/depois para quantificar regressão (H-034 é essa hipótese). Performance ainda superior aos competidores não-zero-alloc (chi, Gin).

**Blast radius:** Critical — quebra silenciosamente apps que migrem de chi/gin/httprouter.

### MM-2026-0004 — RedirectTrailingSlash pre-middleware emission

**Descrição técnica:** Em `mux.go:491-499`, quando `getValue` retorna `tsr=true` e `handler=nil`, o dispatch emite `http.Redirect` directamente — o middleware chain (aplicado via `wrapMiddleware(handler, ...)` em `Handle()`) nunca entra em jogo.

**Exploitability:**
- **Pre-auth:** sim — reconnaissance sem credentials.
- **Remote:** sim — pedido HTTP público.
- **Required conditions:** aplicação regista `/admin/` (com trailing slash). Atacante envia `GET /admin` → 301.
- **Blast radius:** enumera a totalidade dos endpoints com auth.

**Recommended fix (diff sketch):**
```go
// Option 1 — wrap dispatch fallback with middleware chain
// In Mux.New(), after middleware setup:
m.notFoundHandler = wrapMiddleware(http.HandlerFunc(m.dispatchFallback), m.middleware)

// In dispatch, instead of http.Redirect directly:
if tsr && m.RedirectTrailingSlash {
    // emit redirect via wrapped chain
    m.notFoundHandler.ServeHTTP(w, r)
    return
}
```

**Competitor comparison:** chi aplica middleware antes de qualquer decisão de dispatch; MuxMaster é outlier.

### MM-2026-0005 — Allow header + FixedPath pre-auth leak (composite)

**Descrição técnica:** Mesma causa estrutural que MM-2026-0004. Adiciona:
- `OPTIONS /secret` → `204 Allow: GET, POST, OPTIONS` sem auth.
- `GET /admin//console` → `path.Clean` → `/admin/console` → 301 Location com canonical, sem auth.

**Exploitability:** pre-auth, remote, enumera **método matrix** por path + **forma canónica** de paths protegidos.

**Recommended fix:** mesmo refactor do MM-2026-0004 + considerar breaking change: `RedirectFixedPath` default `true → false` (docs normativas no CHANGELOG).

**Blast radius:** complementa MM-2026-0004 para reconnaissance completo. Composto em MM-TM-2026-0001.

### MM-2026-0006 — Logger CRLF/ANSI/NUL injection

**Descrição técnica:** `middleware/logger.go:30` — `fmt.Fprintf(out, "... %s ...", ..., r.URL.Path, ...)`. Stdlib rejeita CRLF literal em request-target (400), mas **percent-decoda `%0D%0A` para `r.URL.Path`**. Logger escreve bytes raw.

**Exploitability:**
- **Pre-auth:** sim (log write acontece em todos os requests).
- **Remote:** sim.
- **Required conditions:** nenhum.
- **Attack scenarios:**
  - **Log forgery:** CRLF injection cria linhas falsas em formato CLF; plausible deniability para traces reais.
  - **ANSI clear:** `%1B%5B2J%1B%5BH` limpa écran em TTY viewer → ofuscação.
  - **NUL truncation:** SIEMs truncam; esconder parte do path.
  - **Right-to-left override:** spoof de URLs em log viewers com bidi support.

**Recommended fix:**
```go
// middleware/logger.go
import "strconv"

func sanitiseForLog(s string) string {
    q := strconv.QuoteToASCII(s)
    return q[1 : len(q)-1]
}

// Em logger.go:30:
fmt.Fprintf(out, "%s %s %s %d %s\n",
    time.Now().Format(time.RFC3339),
    sanitiseForLog(r.Method),
    sanitiseForLog(r.URL.Path),
    rec.status,
    time.Since(start),
)
```

### MM-2026-0007 — compress unbounded buffer

**Descrição técnica:** `middleware/compress.go:25-31` — `g.buf = append(g.buf, b...)` acumula a resposta inteira antes de flush. `g.done` só é true após handler retornar. Handler que escreve 10GB → `g.buf` aloca 10GB (peak ~15-20GB devido a `append` doubling).

**Exploitability:**
- **Pre-auth:** depende do endpoint. Se o endpoint é público + produz responses grandes (image download, API bulk export), atacante envia `Accept-Encoding: gzip` (default de todos os browsers).
- **Required conditions:** nenhum além de `Accept-Encoding: gzip`.

**Recommended fix (diff sketch):**
```go
// middleware/compress.go — streaming instead of buffering
type gzipResponseWriter struct {
    http.ResponseWriter
    gz       *gzip.Writer
    small    []byte // bounded buffer só para sniffing / minCompressSize
    smallMax int
    started  bool
}

func (g *gzipResponseWriter) Write(b []byte) (int, error) {
    if g.started {
        return g.gz.Write(b)
    }
    if len(g.small)+len(b) < g.smallMax {
        g.small = append(g.small, b...)
        return len(b), nil
    }
    // flush small buffer + start streaming
    g.Header().Set("Content-Encoding", "gzip")
    g.Header().Add("Vary", "Accept-Encoding")
    g.Header().Del("Content-Length")
    g.gz = acquireGzip(g.ResponseWriter)
    if len(g.small) > 0 {
        _, _ = g.gz.Write(g.small)
        g.small = nil
    }
    g.started = true
    return g.gz.Write(b)
}
```

## Secção 4 — Compostos multi-agente (zero-day hypotheses confirmadas)

As 3 cadeias de ataque mais preocupantes — todas confirmadas com evidência de múltiplos agentes e promovidas a MM-TM-NNNN.

### MM-TM-2026-0001 — Pre-auth reconnaissance + credential theft pipeline (Critical)

**Agents envolvidos:** HPS + PRF + TSC + MSR. **Findings source:** MM-2026-0004, 0005, 0009, 0020, 0027.

**Ataque ponta-a-ponta (sem auditar nada):**
1. Atacante envia `GET /admin` com `/admin/` registado + auth middleware → `301 Location: /admin/` (MM-2026-0004). Auth middleware **nunca dispara**.
2. Envia `OPTIONS /secret` → `204 Allow: GET,POST,OPTIONS` (MM-2026-0005) — descobre método matrix.
3. Envia `GET /admin//console` → `301 Location: /admin/console` — descobre forma canónica de rotas protegidas.
4. Agora sabe que `/admin` existe e tem auth. Tenta `Basic auth` com `alice:wrong`, `bob:wrong`, `charlie:wrong`... Via Welch p=0 em N=1e5 samples (MM-2026-0009), discrimina usernames válidos vs inválidos (mean diff 319-429 ns).
5. Para cada username válido, itera comprimento da password 1..128 — maximal latency marca o length correcto (MM-2026-0020).
6. Executa online brute-force sem rate-limit (MM-2026-0027), ilimitado.

**Resultado:** infraestrutura enumerada + N utilizadores autenticados, **sem** nenhuma credencial válida ter sido testada até ao passo 6.

**Severity composta:** Critical. É o **diferencial** deste sprint face a auditorias isoladas — nenhum agente individual vê esta cadeia; é apenas visível ao cruzar findings.

**Mitigação recomendada:** fix todos os 5 findings source. TSR/FixedPath/OPTIONS/405 blocks devem passar pelo middleware chain.

### MM-TM-2026-0002 — Multi-channel exfiltration + audit-trail forgery (High)

**Agents envolvidos:** HPS + MSR + DOS + TSC. **Findings source:** MM-2026-0006, 0008, 0011, 0012, 0047.

**Ataque ponta-a-ponta:**
1. Atacante forja IP de "trusted proxy" via `X-Forwarded-For: 10.0.0.1` (MM-2026-0008). Logger regista IP falsificado.
2. Envia request único contendo payload de exfiltração **replicado em 4 canais simultâneos**:
   - `r.URL.Path = /abc%0D%0A<payload>` → log line forgery (MM-2026-0006).
   - `X-Request-ID: <payload>` → reflected no response X-Request-ID header (MM-2026-0011).
   - `Origin: <payload>` → reflected em ACAO se allowAll (MM-2026-0012).
   - `?guess=<payload>` com secret no response body + compress habilitado → BREACH oracle (MM-2026-0047).
3. Atacante correlaciona canais para acelerar exfiltração (2 ou mais canais surviving → confirm bit).

**Severity composta:** High. Logger CRLF também permite **forjar linhas de log que parecem de outro IP** — audit trail é completamente comprometido (no incident response, attacker's real traces são indistinguíveis de linhas forjadas que ele próprio criou).

**Mitigação recomendada:** fix todos os 4 findings source (3 não-aceitáveis + 1 docs-only para BREACH).

### MM-TM-2026-0004 — Concurrency + pool + panic composite (Critical)

**Agents envolvidos:** CSA solo (4 findings de única origem consolidam cross-impacts). **Findings source:** MM-2026-0003, 0014, 0015, 0017.

**Ataque ponta-a-ponta (observação, não exploração directa):**
1. Aplicação Go idiomática tem handler `func(w, r) { go logAsync(r.Context(), ...) ; /* sync work */ }`.
2. Sob load (1000 req/s), algumas goroutines spawn pelos handlers ainda vivas quando main dispatcher restaura `*origCtxPtr = origCtx` e `releaseRC(rc)` → rc volta ao pool.
3. Próximo request pega o mesmo rc; atribui novos `rc.params`. Goroutine antiga, que agora lê `r.Context()`, vê params do **novo** request — cross-request contamination funcional (MM-2026-0003).
4. Se o handler de algum request panica, `releaseRC` skipped (MM-2026-0015) → rc permanentemente leaked. Sob panic storm, heap cresce 5.4 KB/req.
5. Se operador recarrega config em runtime e reconfigura `m.NotFound` (MM-2026-0017) → race no read path.
6. Unit tests paralelos partilhando um Mux → `Use()` race vs `Handle()` (MM-2026-0014) → silenciosamente regista rota com middleware parcial.

**Severity composta:** Critical. É **latent** em produção — não é explorável directamente por atacante, mas produz incidentes de correctness que degradam a confiança na plataforma.

**Mitigação recomendada:** fix conjunto — opção A (substituir unsafe.Add), + defer cleanup, + lock em Use/Pre, + docs de thread-safety contract.

| Compress unbounded buffer | **Confirmed OOM** | N/A | Mesma classe de bug histórica em chi até 2022 | N/A | **MuxMaster com bug já fixado por chi** |

**Conclusão da comparação:**
- Em **4 vectores**, MuxMaster está em igualdade (TSR leak, route-existence timing, XFF trust, smuggling — todos são classes partilhadas por vários routers).
- Em **4 vectores**, MuxMaster é o **outlier (pior) único**: wildcard shadow panic em dispatch (vs outros em addRoute); UTF-8 corruption; race em r.ctx; e `%2F` decoding convention.
- Em **2 vectores**, MuxMaster está em igualdade com chi em classes histórico: compress buffer (chi teve bug equivalente pré-2022).

**Decisão arquitectural principal (MM-2026-0003):** MuxMaster é **único** a usar `unsafe.Add(r.ctx)` entre os routers comparados. Esta escolha ganhou ~5-10 ns por request vs `r.WithContext(...)` mas trouxe race conditions arquitecturais. Remover esta optimização (H-034 benchmark pendente) é o caminho recomendado.
