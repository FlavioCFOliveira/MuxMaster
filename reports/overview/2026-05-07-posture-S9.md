## 0. Executive summary — release recommendation: **HOLD** for v1.2.0

**Verdict:** **HOLD** (do NOT tag v1.2.0 in the current working tree).

S9 surfaced two release-blocking findings that materially break the v1.2.0 promise. Both are in the auth-routing surface — the most critical asset class. Independent of severity score, both create *silent* security regressions that operators cannot detect without writing their own integration tests:

1. **CSA-2026-0060 (sev 8)** — `ParamsFromContext()` silently returns empty params when any `Use()`-registered middleware wraps the request context (Timeout, WithValue, RealIP). An auth handler that reads `:userID` from params and compares to a JWT subject sees `""` and may grant or deny access incorrectly. This affects the canonical Go middleware composition pattern.

2. **FPE-2026-010 (sev 6)** — `Mux.Use(authMW)` followed by `Mux.HandleFast()` silently registers a fast route with NO middleware applied. The Use() docstring explicitly *claims* this panics — but the panic guard from CSA-2026-0054 was only wired to `Group.HandleFast`, not root `Mux.HandleFast`. Operators who read the documentation and trust it are silently exposed.

These two compose into a single silent-auth-bypass narrative (see §5 cluster CL-AUTH-1), and TM-2026-007/008/037 hypotheses already targeted exactly this region. The S9 sprint **confirmed** the hypothesis class is real and exploitable.

A 7-day fix-and-revalidate cycle is recommended before tagging v1.2.0. Both fixes are mechanical (one panic guard, one slow-path fallback) but each requires a regression test plus race-detector run. Severity-7 HPS-2026-0005 (open redirect via absolute-form URI) is not a blocker per se but should ride in the same point release.

Net delta vs S8 posture: **5 fewer R cells in STRIDE, but 2 new R cells via S9 findings → net 3 fewer**. Architecture is materially safer than S8 except for the two new auth-relevant regressions surfaced by S9.

## 3. Cluster analysis — overlapping findings across agents

S9 findings cluster into root-cause groups. Each cluster represents one logical bug (with multiple manifestations across agents) and should be fixed once.

### CL-AUTH-1 — Silent auth bypass via context/middleware composition (CRITICAL)

**Root cause:** the public auth/middleware contract assumes Use() composes correctly with HandleFast and with WithContext-wrapping middleware. Both assumptions are violated.

| Finding | Agent | Manifestation |
|---|---|---|
| **CSA-2026-0060** (sev 8) | concurrency | params.go type-switch fails when ctx is wrapped → empty params in handler |
| **FPE-2026-010** (sev 6) | fuzzing | Mux.Use + HandleFast silently skips middleware (no panic guard) |
| TM-2026-007 (sev 5) | hypothesis | Group-mounted handler bypasses Pre-registered JWT |
| TM-2026-008 (sev 4) | hypothesis | UseFast on Group bypasses Pre when registration order varies |
| TM-2026-036 (sev 4) | hypothesis | Group middleware ordering allows skip |
| TM-2026-037 (sev 3) | hypothesis | UseFast bypasses Use auth gate via accidental fast-route registration |
| FPE-2026-007 (sev 5) | fuzzing | Property test missing for Use→HandleFast panic guard |

**Fix scope:** params.go (slow-path ctx.Value fallback) + mux.go (root HandleFast panic guard) + property tests (FPE-007). Total ~80 LOC + 4 regression tests.

**Cross-agent escalation:** confirmed silent-bypass narrative. The TM-007/008/037 hypotheses are now CONFIRMED-IN-PART (the auth-bypass class exists; specific Group/UseFast variants need a follow-up audit in v1.2.x).

## 4. Cross-agent composite escalation: CSA-0060 + FPE-010

**Convergence narrative:**

These are two faces of the same architectural problem: **MuxMaster's middleware contract is inconsistent across the (Use/Pre/UseFast) × (Handle/HandleFast) × (root/Group) combinatorial surface.**

- FPE-010 manifests at registration time (no panic where one is documented).
- CSA-0060 manifests at request time (params lost in handler when ctx is wrapped).

Together they invalidate the operator mental model summarised in CDX-S8-003: *"Pre is the only family that uniformly covers BOTH route types."* The CDX-S8-003 invariant remains true — but a developer who relies on Use() + HandleFast or on ParamsFromContext() in a Use(Timeout)-wrapped handler is silently broken.

**Composite hypothesis (escalated):** can an attacker trigger both at once?

```
Hypothesis CL-AUTH-COMPOSITE-1:
  Operator writes:
    mux.Use(Timeout(10*time.Second))
    mux.Use(JWTAuth(opts))           // validates :userID == jwt.sub
    mux.HandleFast("GET", "/api/users/:userID", handler)   // ← PANICS NOT (FPE-010)
  Even if registered without panic, JWTAuth is skipped (FPE-010).
  Even if JWTAuth runs (in a non-fast variant), it sees ParamsFromContext == empty (CSA-0060).
  Result: handler invoked with neither auth nor route params → DOUBLE silent bypass.
```

This composite is the **paramount finding of S9**. Both fixes must land together.
