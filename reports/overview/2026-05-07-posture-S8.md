## Executive summary

Sprint S8 was the **post-S1..S7 fix re-audit + delta hunt** required before tagging v1.2.0. Eight specialist agents ran the playbook from `/reports/overview/2026-05-07-sprint-S8.md` covering 56 attack surfaces (AS-001..AS-211) and 60 hypotheses (H8-01..H8-76).

**Outcome:** **16 new findings filed**, distributed sev 1-7 (no sev 8/9). **Zero new release-blockers.** Three high-impact specialists (`go-sast-and-memory-auditor`, `dos-resilience-tester`, `timing-and-sidechannel-analyst`) returned clean — the post-S2 fixes for `cfg` atomic generation, `Use()` lazy snapshot, two-phase registration, optional-cap=8, raw-byte tree indices, and singleflight all held under aggressive re-probing.

The 16 new findings cluster in three areas: (a) **operator-misconfiguration footguns** (RealIP/Throttle/JWT/OAuth2 hardening defaults — 4 of 5 MSR findings), (b) **input-validation tightening** (PRF + FPE: 5 findings, mostly low-severity parser edge cases and harness defects), (c) **documentation/observability gaps** (logger sanitisation, Pre-vs-Use boundary, panic-handler double-panic).

**Verdict: GO-WITH-CONDITIONS for v1.2.0.** Conditions:
1. Ship #73 (OAuth2 plaintext HTTP — sev 7) fix in v1.2.0. This is the single highest-severity outstanding issue and represents an unconditional security regression for any operator that follows the documented usage.
2. Ship #75/#77 (Logger r.Method CRLF — sev 4, deduplicated) fix in v1.2.0. One-line change.
3. Document the Pre/Use × Handle/HandleFast 4-cell matrix (CDX-S8-003) in CLAUDE.md and SECURITY.md — without code change.
4. All other findings (sev ≤ 5 + cosmetic) may slip to v1.2.1 with explicit SECURITY.md entries acknowledging the residual risk.

The release is no longer blocked by zero-day class defects. The remaining ledger is hardening + ergonomics.

## Release recommendation: **GO-WITH-CONDITIONS for v1.2.0**

### Required for v1.2.0 tag (block release until done)
1. **#73 OAuth2 HTTPS enforcement** — reject http:// introspection endpoints at construction (panic) or behind explicit `AllowInsecureTransport=true` opt-in. CWE-319.
2. **#77 Logger r.Method sanitisation** — single-line change to wrap r.Method in `sanitiseForLog`. CWE-117. Closes #75 too.
3. **CDX-S8-003 / #86 documentation only** — Pre/Use × Handle/HandleFast 4-cell matrix in CLAUDE.md and SECURITY.md. No code change.

### Recommended for v1.2.0 (ship if time permits, else explicit SECURITY.md)
- **#71 RealIP** — provide an opinionated `RealIPFromTrustedProxy(n int)` constructor; document leftmost vs rightmost.
- **#72 JWTAuth.RequireExpiry** — add option, keep default false for back-compat, document recommendation true.
- **#74 ThrottlePerIP.MaxTableSize** — add bound with sane default (e.g. 100k entries), LRU eviction.
- **#76 SetHeader+CORS ordering** — runtime warn at chain construction.
- **#79 UseRawPath %2f** — SECURITY.md hardening note + example.

### Defer to v1.2.1 (file in CHANGELOG-NEXT)
- All sev ≤ 3 and cosmetic items: #78, #80, #83, #84, #85, #81, #82.
- Composites #87, #88: tracked but blocked by their constituents.

## Sprint retrospective

What worked:
- Two-phase plan (sprint plan with 56 AS-IDs and 60 hypotheses) gave specialists unambiguous scope. Cross-agent escalation matrix in §5.3 was used twice (CRLF in r.Method discovered by MSR escalated to HPS, who filed canonical #77).
- Specialists who returned clean (DOS, SAS, TSC) did so with concrete harness counts (e.g. DOS produced 14 regressive tests refuting H8-04/06/25/47/49/50/56). Negative results are valuable.
- Composite tracking via CDX entries with rmp `add-dep` chains lets composites auto-close on constituent closure.

What to change:
- Initial duplicates (MSR-2026-0069 vs HPS-2026-0001) reflect that two agents independently found r.Method CRLF — useful as cross-validation, but file naming would benefit from a fast-path to suggest the canonical owner before filing.
- Some hypotheses (H8-29 reflection panic, H8-65 OpenSSL transposition) were marked NOT-EMPIRICAL but no harness exists; either drop them from H-list or commit to write the empirical harness.
