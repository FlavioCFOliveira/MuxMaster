# Security Posture Report — 2026-05-07 (Pre-release v1.2.0)

**Roadmap:** muxmaster · **Sprint:** id=1 (OPEN) · **Commit:** f4faa54 · **Go:** 1.26.2

---

## Executive summary

Audit phase 2 (eight specialists in parallel) produced **55 ledger entries** in the rmp roadmap, of which **5 are sev=9 Critical**, **5 sev=8 High**, **9 sev=7 High**, the rest Medium/Low/SAFE-confirmation. Every one of the ten zero-day hypotheses from the §2.4 sprint plan was investigated; **9 of 10 were confirmed** (one — JWT alg-confusion via shared key material — was REFUTED but a related timing oracle was confirmed instead). A new sev=9 Critical (PRF-2026-0009 — multi-byte UTF-8 OOB panic at `addRoute`) was discovered outside the original hypothesis set.

The release **cannot ship** in its current state: three independent sev=9 fault lines (Rebuild/cfgOnce race, Use/lazy-cache race, multi-byte UTF-8 addRoute panic) and one structural sev=9 trap (Group.Use silent-bypass on HandleFast) each constitute a release-blocking defect.

**Verdict: NO-GO.** Iterate Sprint 1 to closure on all sev≥8 entries before tagging v1.2.0. SAST is clean; the issues are concentrated in concurrency contracts, the new HandleFast trust-boundary, the new optional-segment feature, and middleware composition footguns. None of the issues require an architectural rethink — they are bounded fixes.

## Top 5 composite zero-day candidates (cross-agent combinations)

These are not single-agent findings — they are vectors that emerge only when two or more specialists' findings compose. None of them is yet a filed task; the orchestrator opens them as **CDX (composite)** entries in `findings.md` for follow-up.

### CDX-1 — Silent-unauth + missing-recovery + raw-path log = single-request takedown

**Combines:** CSA-2026-0054 (HandleFast skips Use auth) + CSA-2026-0053 (HandleFast also skips Recoverer) + MSR-2026-0057/MSR-RE-V2-001 (raw `r.URL.Path` to slog).

**Vector:** A misconfigured Group with `g.Use(authMW); g.HandleFast(/secret, h)` yields an unauthenticated route. If `h` panics, the panic propagates past the dispatch recovery (Recoverer is not in the chain), is caught by the Mux-level `dispatchWithRecover` only if `m.PanicHandler` is set; the path used to drive the panic is then logged raw, allowing the same attacker to inject log lines on every probe. Three-finding chain, single curl loop, no auth required.

**Severity escalation:** sev=9 (each component is sev=8/9 individually; chained is operationally trivial).

### CDX-2 — Multi-byte addRoute panic + dynamic registration + no two-phase commit

**Combines:** PRF-2026-0009 (UTF-8 OOB panic in `incrementChildPrio`) + MM-2026-0033 (tree corruption superficial after panic) + MM-2026-0050/PRF-2026-0007 (`expandOptional` 2^N).

**Vector:** Operator (or untrusted plug-in) registers `/foo{/:id}é` → panic mid-registration → tree left in partially-modified state → subsequent `Walk`/`Routes`/`Lookup` returns UB → panic propagates to startup if registration is at boot, **or** silently corrupts the tree at runtime if dynamic registration is permitted. The exponential-expansion path enlarges the corruption blast radius.

**Severity escalation:** sev=9 (combination of fail-fast at boot **and** silent corruption mid-runtime depending on call-site).

### CDX-3 — XFF-unconstrained RealIP + Throttle-before-RealIP + per-IP map bloat

**Combines:** MSR-2026-0055 (RealIP() trusts all peers without CIDR) + DOS-2026-0002 (Throttle before RealIP collapses to global limit) + DOS exhaustion of per-IP map.

**Vector:** Configuration trap: operators register `r.Use(throttle); r.Use(realIP())`. Behaviour A: per-IP throttle becomes a global throttle (one attacker DoSes all clients). Behaviour B: if order is reversed and CIDR is empty, attackers spoof XFF to bypass throttle entirely. Either configuration is exploitable; the **error in the wrong direction** depends only on operator order. No combination is safe by default.

**Severity escalation:** sev=8 (architectural: requires explicit operator-side defence).

### CDX-4 — UnescapePathValues double-decode + Catch-all raw filepath + handler that re-decodes

**Combines:** PRF-2026-0006 (`%2520` double-decode) + PRF-2026-0005 (catch-all param contains raw traversal) + PRF-2026-0002 (`%61dmin` matches `/admin`).

**Vector:** Operator enables `UnescapePathValues=true` (often suggested for ergonomics) and uses a catch-all `*filepath`. Attacker submits `/static/%2525%32%65%2525%32%65/etc/passwd`; net/url decodes once, dispatch's `url.QueryUnescape` decodes again, the handler that does its own `path.Clean` or `url.PathUnescape` decodes a third time. The traversal segment that was supposed to be blocked at validation-time bypasses every layer.

**Severity escalation:** sev=8 (combination of three single-decoder bugs that look small in isolation).

### CDX-5 — JWT alg-path timing oracle + OAuth2 cache hit/miss timing + route-existence timing = full IdP fingerprint

**Combines:** TSC-2026-0003 (HS256 vs RS256: 25 µs gap) + TSC-2026-0007 (OAuth2 cache hit vs miss: 143 µs gap) + TSC-2026-0005 (route-existence oracle).

**Vector:** Three independent latency channels combine to identify, in fewer than 100 requests, whether: (1) a token uses HMAC vs RSA, (2) the token was previously seen by another client, (3) any given path is registered. The third oracle was previously accepted as intrinsic (MM-2026-0026); the new two compound it to enable user-correlation attacks across tokens (privacy violation in shared tenancies). Individually each is documented as accepted; combined they expose coarse IdP topology.

**Severity escalation:** sev=7 (privacy/recon; not a direct compromise).

## Sprint retrospective notes

- Cross-agent overlap was high (~10 of 55 tasks). For Sprint 2, dispatch should explicitly assign primary owner per finding-class to avoid duplicate filings.
- The HandleFast trust-boundary was the single largest source of new findings — three agents independently confirmed it. Consider promoting it from "documented" to "compile-time error" before v1.2.0.
- The original 10 hypotheses from §2.4 were good predictors: 9 of 10 yielded findings. Hypothesis #1 (alg-confusion) refuted-via-logic but yielded a stronger timing finding — a valuable "second-order" pattern to keep in future sprints.
- Specialist write-up format diverged: SAST produced a single MD; others left only evidence trees + rmp tasks. Standardise to require an executive-summary MD per agent for consolidation.
