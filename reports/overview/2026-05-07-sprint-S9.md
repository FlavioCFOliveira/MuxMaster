The S8 posture report mandated specific code changes for v1.2.0. The current working tree shows their implementation. Each delta is a fresh attack surface for S9:

| S8 finding closed | New code introduced | Audit risk |
|---|---|---|
| #73 OAuth2 HTTPS (CWE-319) | `middleware/oauth2.go`: panic on non-https + `AllowInsecureEndpoint` opt-in + slog.Warn at construction | (a) is `url.Parse` lenient enough that `https://attacker@evil/x?u=https://idp.com` triggers the wrong scheme check? (b) does the `AllowInsecureEndpoint` slog.Warn leak the endpoint URL with credentials? (c) is the panic message a log-injection vector if `opts.Endpoint` contains CRLF? |
| #77 Logger r.Method CRLF (CWE-117) | `middleware/logger.go`: wrap r.Method in `sanitiseForLog`. Plus FPE-2026-0002 doc note that `sanitiseForLog` is NOT idempotent | (a) does `strconv.QuoteToASCII` cope with malformed UTF-8 in r.Method? (b) other log fields bypassed (User-Agent, Referer, X-Request-ID)? (c) does double-application appear via Recoverer + Logger composition? |
| #72 JWT RequireExpiry | `middleware/jwt_auth.go`: `RequireExpiry bool` option threaded through `parseAndValidateJWT` | (a) does `RequireExpiry=false` (default) re-create the original vuln (token without exp valid forever)? (b) `raw.Exp == 0` — what if attacker submits `"exp": null` or `"exp": -1` or `"exp": 9.99e99`? (c) JSON parsing for exp silently coerces float→int losing precision near 2038? |
| #74 ThrottlePerIP MaxTableSize | `middleware/throttle.go`: `ThrottlePerIPCapped` + `DefaultThrottlePerIPMaxTableSize=100k` + reject on full | (a) is the cap atomic w.r.t. `len(table)`? (b) at saturation, can attacker hold ALL slots forever and prevent legitimate keys from registering? (c) the `decRefs` helper appears defined but unused — dead code? Race window? (d) reject path is 503 — does it carry a Retry-After? does it honour timeout context? |
| #71 RealIP rightmost-walk | `middleware/real_ip.go`: `selectXFFRightmost` walking right→left through trusted CIDRs | (a) what if CIDR list contains overlapping entries? (b) IPv6 zone IDs in CIDR (`fe80::%eth0/64`)? (c) entire chain trusted → "leftmost as last resort" is exactly the H8-65 leftmost-XFF spoof we just fixed — is this regression? (d) what if XFF contains `0.0.0.0`, `127.0.0.1`, multicast, link-local? |
| #76 SetHeader+CORS doc | `middleware/cors.go` + `set_header.go`: doc-only ORDERING note | (a) is the doc accurate? CORS in S8 was identified as innermost overwrites — verify the actual frame order at runtime via test |
| CDX-S8-002 ServeFiles UseRawPath panic | `mux.go`: panic at `ServeFiles` registration when both flags set, plus one-time slog.Warn at first Handle/HandleFast | (a) registration order — Handle before ServeFiles or ServeFiles before Handle — does the warn fire? (b) is the warn a goroutine-safe sync.Once that survives Rebuild()? (c) panic recovery: if a test sets both flags then calls ServeFiles inside a goroutine, panic kills test? |
| CDX-S8-003 Pre vs Use boundary | `mux.go`: doc additions on Use, Pre, UseFast | (a) doc-only, no code change — verify doc matches behaviour |
| CSA-2026-0058 PanicHandler doc | `mux.go`: doc on PanicHandler must-not-panic | (a) doc-only — but verify net/http per-conn fallback is reachable in HTTP/2 multiplexed streams |

## 4. Hypothesis catalogue (S9-NEW) — assigned to specialists

### 4.1 Generation methodology
- **Delta-driven** (§1): every line of new code in the working tree
- **STRIDE-driven** (§2): every Y cell that didn't go to G
- **Tree-driven** (§3): every leaf
- **Composition-driven**: every ordered pair of changed middleware (logger×oauth2, real_ip×throttle, cors×set_header) — the "did anyone test the *interaction*?" question
- **Cross-ecosystem** (§3.F): each recent CVE in transposition.md scanned against MuxMaster architecture

### 4.2 Severity / priority calibration
- **9** = release-blocker, immediate fix required
- **7-8** = exploitable with realistic preconditions, fix in v1.2.0
- **5-6** = exploitable with operator misconfiguration, fix in v1.2.x
- **3-4** = doc-fix, telemetry, or hardening default
- **1-2** = cosmetic / engineering quality

### 4.3 Hypothesis ledger (TM-2026-NNN)

The full list of TM hypotheses is in §3 (attack-tree leaves). Each has been registered as a rmp task — see §6 for the IDs.

The hypothesis catalogue is also stored in the rmp roadmap as tasks `TM-2026-001..051` (sprint id=9). For each task:
- `severity` and `priority` follow §4.2
- `functional_requirements` cites the source CVE / class / transposition origin
- `technical_requirements` names the file:func + the assigned specialist
- `acceptance_criteria` is "validate reproduction; classify confirmed/refuted/needs-testing; document in /reports/<agent>/"
