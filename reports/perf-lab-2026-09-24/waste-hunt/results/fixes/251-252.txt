## Findings summary
======================================================================
WH-01 (middleware/throttle.go): DONE. Non-blocking fast path (select probe
before creating a timer) + throttleEntry recycling via
throttleTable.entryPool. CH-01/CH-02 sharding/exact-cap/no-lost-wakeup
properties untouched and re-verified with -race.

WH-02 (middleware/logger.go): DONE. Single end-of-request time.Now() serves
both the timestamp and the duration. appendSanitisedForLog / appendLogDuration
append directly into the pooled buffer (0 allocs/op, down from 5).

WH-07 (middleware/logger.go): DONE. statusRecorder.ReadFrom delegates to the
underlying ResponseWriter's io.ReaderFrom via a writerOnly-wrapped io.Copy
fallback. strace evidence above: 3/3 sendfile(2) calls preserved.

WH-03 (middleware/compress.go): DONE. gzipResponseWriter now carries a fixed
[8192]byte sniff array (arr) as part of its own allocation and is recycled
through a sync.Pool (rwPool), fully reset (`*grw = gzipResponseWriter{}`)
before every Put — including on the panic path, verified by
TestCompress_PoolHygiene_PanicDoesNotLeakStateToNextRequest. The 404->200
WriteHeader defect is untouched (explicitly out of scope).

WH-06 (middleware/jwt_auth.go): PARTIALLY DONE, with one sub-finding
INVESTIGATED AND REJECTED after measurement (see below).
  - Header memo: DONE. decodeJWTHeader caches the (header bytes -> alg)
    result of the LAST accepted header per JWTAuth instance in an
    atomic.Pointer[jwtHeaderMemo]. A header is stored ONLY after passing
    the alg allow-list and RFC 7515 crit check; verifyFn (signature
    verification) still runs unconditionally on every request. Proven with
    dedicated bypass tests: memo hit + tampered signature still 401; memo
    hit + disallowed alg still 401 and never poisons the cache; two
    JWTAuth instances never share a memo; -race stress with concurrently
    alternating header byte sequences.
  - signingInput copy removal: DONE. bytesFromString (unsafe.Slice over
    unsafe.StringData) replaces `[]byte(signingInput)`. Measured: 25.45 ns/
    80 B/1 alloc -> 0.68 ns/0 B/0 allocs (scratch benchmark).
  - hmac.Sum(nil) -> stack array: NOT APPLIED. Investigated per the
    project's "measure, don't guess" rule and REJECTED: h has static type
    hash.Hash (an interface — p.p.Get() gives escape analysis no concrete
    type), so h.Sum(buf[:0]) forces ANY caller-local buf to escape to the
    heap on EVERY call, identically to h.Sum(nil). The waste-hunt report's
    "+12 ns/+32 B/+1 alloc" figure for this sub-finding was produced by a
    micro-benchmark that declared the stack array ONCE, above the b.N
    loop — hoisting a single one-time heap escape and amortising it toward
    zero over many iterations, which cannot happen in real per-request code
    (each request needs its own buffer). Re-measured with a buffer declared
    fresh per call, as production code requires:
      Sum(nil):            141.7 ns/op   32 B/op   1 allocs/op
      Sum(stack, per-call): 147.3 ns/op   64 B/op   1 allocs/op
    Sum(nil) is strictly better; kept unchanged. See the doc comment on
    jwtHMACPool.verify in middleware/jwt_auth.go for the full analysis.

WH-11 (middleware/real_ip.go): DONE. selectXFFRightmost scans xff from the
right with strings.LastIndexByte, no allocation, same maxXFFHops=30 bound.
Pinned against an independent reference oracle (the pre-existing
strings.Split algorithm, reproduced in the test file) over a table of edge
cases (spaces, empty entries, IPv6, IPv6 zones, ported/bracketed invalid
entries, many-hops) plus a 50000-header random-corpus fuzz-equivalence test,
both with and without a trust list.

WH-12 (middleware/api_key.go): DONE. apiKeyCtx fuses the context node and
the identity string into one allocation (same technique as requestIDCtx).
TSC-2026-0008 header Set+Del timing equalisation left byte-for-byte
unchanged.
