# MuxMaster v1.2.0 — Release Notes

**Version:** v1.2.0
**Date:** 2026-09-26
**Type:** Minor — backward-compatible additions, bug fixes, and security hardening
**Module:** `github.com/FlavioCFOliveira/MuxMaster`
**Go:** 1.26 or newer (unchanged)
**Previous release:** v1.1.0 (2026-05-12)
**Comparison:** [v1.1.0...v1.2.0](https://github.com/FlavioCFOliveira/MuxMaster/compare/v1.1.0...v1.2.0)

---

## Executive summary

MuxMaster v1.2.0 adds first-class support for the HTTP QUERY method (RFC 10008), fixes a set of routing, `Mount`, `Group`, and middleware defects, hardens redirects and four middleware against security weaknesses, and removes waste from route registration and several middleware. It is the product of sprints 18 to 21: 88 commits since v1.1.0.

The exported API is a strict superset of v1.1.0. `apidiff` against the v1.1.0 tag reports six compatible additions and no incompatible change in the root package, and no change at all in the `middleware` package. The module still has zero external dependencies.

Several fixes change observable behaviour. Most of them turn a panic, a wrong status, or a silently corrupted response into the documented result, but some programs can notice the difference. Read [Upgrade notes](#upgrade-notes) before you upgrade.

---

## Highlights

- **HTTP QUERY method (RFC 10008).** New `MethodQuery` constant and `Mux.QUERY`, `Mux.QUERYE`, `Mux.QUERYFast`, `Group.QUERY`, and `Group.QUERYE`. `ANY` now registers QUERY, the `Allow` header lists it, and the router's own redirects on QUERY routes use `307` so the method and body are preserved. Go's `net/http` does not yet define `http.MethodQuery` (golang/go#80058); `MethodQuery` is guaranteed to equal `"QUERY"`.
- **`Mount` works correctly with nested routers.** An inner `*Mux`'s own trailing-slash and fixed-path redirects now keep the mount prefix in `Location`; `RawPath` is propagated through parameterised prefixes; a prefix that ends in an optional parameter panics at registration with a message that names the cause.
- **Routing correctness.** A named or regex parameter no longer captures an empty path segment; a static route can be registered next to a parameter sibling in either order; a request that does not match a static branch falls back to its parameter sibling; an unclosed `{` panics instead of silently overwriting a route; parameter routes no longer panic on a request whose context is `nil`.
- **Security hardening.** Redirect targets percent-encode `\` as `%5C` and control bytes per RFC 9110; `BasicAuth` looks users up in constant time; `CORS` adds `Vary: Origin` to every response; `OAuth2Introspect` no longer prints credentials in panics and keeps request-scoped context values in shared introspection calls; `Recoverer` no longer appends its 500 body to a response the handler had already started.
- **Faster registration and leaner middleware.** Registration copies O(depth) instead of O(tree size) (5 000 routes: 2.86 s → 4.7 ms). `ThrottlePerIP`, `Logger`, `Compress`, `JWTAuth`, `RealIP`, `APIKey`, `RequestID`, and `OAuth2Introspect` cost less time or fewer allocations. The request hot path allocates exactly as much as in v1.1.0.

## Upgrade notes

The list below covers every change a program written for v1.1.0 can observe. Each item was reproduced by running the same probe program against the v1.1.0 tag and against the release commit (Go 1.27.0, linux/amd64).

### Changes that can make a working v1.1.0 program behave differently

| Change | v1.1.0 | v1.2.0 | What to check |
|---|---|---|---|
| **Group prefix join** (rmp #282). `Group("/api/")` followed by `GET("/users")` | Registers `/api//users` (plain concatenation, as the v1.1.0 specification stated) | Registers `/api/users`; exactly one `/` is dropped at the join | Groups whose prefix ends in `/`. If the program also registers the joined path directly (for example `mux.GET("/api/users")`), registration now **panics** with a duplicate-route error. Applies to `Group.Handle`, `Group.HandleFast`, `Group.Group`, `Group.Mount`, and `Group.ServeFiles`. |
| **`ANY` includes QUERY** | A QUERY request to an `ANY` route gets `405` (or `404`) | The `ANY` handler receives it | `ANY` handlers that assume a fixed method set. |
| **Empty segments no longer match parameters** (rmp #283). `/:id/posts` against `//posts` | `200`, `id = ""` | `404` (or the ordinary redirect sequence) | Clients that relied on a doubled `/` reaching a parameter route. |
| **Static-to-parameter fallback** (rmp #259). `/users/list` and `/users/:id`, request `/users/listx` | `404` | `200`, `id = "listx"` | Parameter handlers must validate values that begin with a static sibling's name. |
| **`CORS` sends `Vary: Origin` on every response** (rmp #291, TM-2026-033) | Only on a matched, non-wildcard origin | Always, including requests without `Origin` and CORS's own 400/403 responses | Caches and tests that assert exact `Vary` values. Cost: +1 allocation (112 B) and about +45 ns on the no-`Origin` path. |
| **`Recoverer` after a started response** (rmp #276) | Appends `Internal Server Error\n` to the body already written | Leaves the started response untouched; the panic is still logged | Tests that assert the appended text. |
| **`Mount`, `ServeFiles`, `CleanPath`, `StripSlashes` build a shallow request copy** (rmp #250) | `r.Clone()`: the inner handler received its own header map | The copy shares the header map and context with the original, as `http.StripPrefix` does | A mounted handler that mutates `r.Header` is now visible to outer middleware that reads `r.Header` after `next.ServeHTTP` returns. |
| **Trailing-slash redirect for catch-all routes and bare `Mount` prefixes** (rmp #255) | `/api` for `Mount("/api", h)` and `/s` for `GET("/s/*fp")` return `404` | `301` to `/api/` and `/s/` (when `RedirectTrailingSlash` is `true`, the default) | Clients that call the bare prefix. |
| **Redirect `Location` encoding** (rmp #260, #279) | `\` and control bytes copied verbatim | `\` becomes `%5C`; bytes 0x00–0x1F and 0x7F are percent-encoded | Redirect targets that contain those bytes. |

### Changes that turn a failure into success

- A static route registered after a parameter sibling (`/books/:id`, then `/books/featured`) no longer panics.
- A parameter route no longer panics when `ServeHTTP` receives a `*http.Request` built as a struct literal (nil context).
- An inner `*Mux`'s own redirect through `Mount` now keeps the mount prefix (`/api/users` → `/api/users/`, previously `/users/`).
- `StripSlashes` keeps `RawPath` consistent with `Path` for an encoded trailing slash (`/a%2f`).

### Changes that turn silent corruption into a registration panic

- A pattern with an unclosed `{` (for example `/a/{id`) panics with `muxmaster: regex param '{' in path '<pattern>' is missing its closing '}'`. In v1.1.0 it silently replaced the handler of an existing route. Programs that start successfully on v1.1.0 but contain such a pattern will panic at startup on v1.2.0; the pattern was never routable as intended.
- A `Mount` prefix that ends in an optional parameter still panics, but the message now names the prefix and the cause.

## Fixes

The complete list, with rationale, specification references, and regression tests, is in the [`[1.2.0]` entry of CHANGELOG.md](../CHANGELOG.md#120---2026-09-26). Beyond the items above, it covers:

- `Compress` and `Logger` implement `http.Flusher` and `Unwrap()`; `Logger` also implements `io.ReaderFrom`, so `sendfile` stays available behind it.
- Registration rollback: a registration that panics mid-insert leaves the live tree untouched.
- Five examples that panicked at startup (`authn`, `cache`, `jwt`, `static-site`, `rest-api`) now start; `reverse-proxy` no longer fails under `PoolRequestBundle = true`.
- Documentation, GoDoc, `api.md`, and the specification were checked against the code and corrected (sprint 21), including the statement that custom HTTP methods are **not** supported: the method set is closed, and `Handle("PURGE", ...)` panics, as it already did in v1.1.0.

### Request hot path: unchanged

The 18 routing benchmarks shared by v1.1.0 and v1.2.0 have **identical B/op and allocs/op**. With three samples per side, `benchstat` marks every ns/op delta as not significant; read the ns/op columns as point estimates, not as a regression or an improvement.

| Static route | 26.95 | 28.63 | 0 | 0 |
