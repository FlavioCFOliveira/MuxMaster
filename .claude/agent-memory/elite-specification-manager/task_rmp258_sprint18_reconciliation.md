## What changed

1. **routing.md rule 51** (§4.3): removed the "regex falls through to plain param" requirement (never true — the tree holds exactly one wildcard child per node, so a regex and a plain param can never coexist at one position). Rule 71 (§5) now states explicitly that a regex param and a plain named param at the same position conflict, panicking regardless of registration order.
2. **routing.md new §6 "Lookup Fallback"** (rules 72-77): documents DIV-001 (rmp #259) — a failed static branch backtracks to a wildchild sibling at the same position (`/users/list` + `/users/:id` → `/users/listx`/`/users/lis` resolve to `:id`), no depth limit, cost bounded by tree node count (see `tree.go`'s `backtrackStack` doc comment for the proof this paraphrases).
3. **routing.md new §7 "Static and Wildcard Sibling Registration"** (rules 78-79): static-vs-named/regex-param sibling registration is legal in either order (MM-2026-0256, rmp #256); catch-all-vs-static sibling still conflicts in both orders (via rule 68 or rule 71 depending on order).
4. **routing.md new §8 "Redirect Target Encoding"** (rules 80-81): TSR/fixed-path redirects percent-encode ASCII CTL/DEL bytes in the `Location` target and HTML body link (RFC 9110 §5.5); otherwise byte-identical to `net/http.Redirect` (rmp #260/#248). Confirmed via code that the public `muxmaster.Redirect()` helper (response.go) does NOT get this treatment — it's a bare passthrough to `http.Redirect`, matching response-helpers.md rule 23 already — so this rule belongs only in routing.md, not response-helpers.md.
5. **routing.md rule 52** (§4.4 TSR): added a third sub-bullet clarifying TSR applies equally when the trailing-slash form is reached only through a catch-all or `Mount` (rmp #255 fix).
6. **groups.md rule 28** (Mount): corrected — a mount's bare prefix (no trailing slash) does NOT match the catch-all directly; it 404s or TSR-redirects to the trailing-slash form depending on `RedirectTrailingSlash`. Previous text incorrectly implied the bare prefix "handles" directly.
7. **middleware.md rule 11**: TSR/fixed-path redirects ARE wrapped by `Use`-registered middleware (serveRedirect reads the live `redirectMWPtr` snapshot, refreshed on every `Use()` call — confirmed in mux.go). Rewrote to state this, and to note the redirect's middleware binding is dynamic (reflects the latest `Use` chain at emission time), unlike route handlers' fixed-at-`Handle()`-time binding. Left the NotFound/MethodNotAllowed/OPTIONS "not wrapped" clause in the same rule untouched — see contradiction #1 below.
8. **middleware-stdlib.md**: full rewrite, renumbered rules 4→70 (was 4→62; net +8 rules, no rule count changed for sections not listed below). No external file references specific rule numbers in this file (verified by grep) so renumbering was safe.
   - §2 Logger: recorder forwards every `WriteHeader` call to the client unchanged (only the *recorded* status for the log line is first-call-wins); 1xx codes (except 101) never latch the recorded status; recorder implements `http.Flusher`/`Unwrap`; recorder implements `io.ReaderFrom` delegating to the underlying writer (preserves `sendfile`/`splice` via `http.ServeContent`/`ServeFile`).
   - §5 RealIP: full rewrite. Actual signature is `RealIP(trustedCIDRs ...*netip.Prefix)` (NOT `RealIP()`) — peer must be inside a trusted CIDR before XFF/X-Real-IP is even consulted. XFF selection is a **rightmost-untrusted-hop** algorithm (scans from the right, skips trusted hops, first untrusted hop wins; falls back to leftmost if the whole chain is trusted or no CIDRs given), bounded to the rightmost 30 comma-separated entries (`maxXFFHops`). This was a *complete* behavior rewrite from the old spec ("first IP in the list, no CIDR validation") — read `middleware/real_ip.go` in full before touching this section again.
   - §8 Compress: added first-WriteHeader-wins/1xx-exempt status semantics, `Flush`/`Unwrap` support, and a note that the pooled `*gzip.Writer`/wrapper recycling is an internal optimization only.
   - §14 SetHeader: added the previously-undocumented construction-time panic on CR/LF in key or value; corrected the per-request mechanism from `w.Header().Set` to a direct canonical-key map write with a fresh per-request `[]string{value}` slice (same observable header).
9. **performance.md rule 36**: `maxParams` is tracked ONLY on the tree's root node (a single "does this tree have any params anywhere" flag), never per-node — confirmed via grep across tree.go/mux.go that `.maxParams` is only ever written on `origRoot` and only ever read on tree roots (`root.maxParams`, `starRoot.maxParams` in mux.go). The *previous* reconciliation pass ([[task_rmp250_253_perflab_spec]], 2026-09-24) had written "updated incrementally on each node along the copied insertion path," which was itself wrong — the code updates only the root, in one `defer` per top-level `addRouteInternal` call. Lesson: a same-day-old "already fixed" memory claim can still be stale; re-derive from a fresh grep, don't trust the prior fix's own description without re-checking.
10. **out-of-scope.md**: removed the "OAuth2 or JWT middleware" exclusion (§5 list) and rewrote §2.6 — `JWTAuth` (`middleware/jwt_auth.go`) and `OAuth2Introspect` (`middleware/oauth2.go`) are fully implemented, narrow, low-level primitives (same class as `BasicAuth`), not full auth systems (session/RBAC/policy remain out of scope). Both fixes bundled together since they assert the identical fact in the same file.

## Contradictions found — both resolved same session per explicit user decision (2026-09-25, same day)

1. **NotFound/MethodNotAllowed/OPTIONS auto-response ARE wrapped by `Use` middleware too.** Initially flagged as out-of-scope-for-#258 and left unfixed; the user then explicitly authorized fixing it under #258. Confirmed via code: `lazyNotFound`, `lazyMethodNotAllowed`, and `lazyOPTIONS` (mux.go) all call `wrapMiddleware(handler, m.middleware)` before caching (mw read fresh under `m.mu.RLock()` at build time), all three caches are invalidated by every subsequent `Use()` call and by `Rebuild()`, and all three are on the live `ServeHTTP` dispatch path (mux.go ~1279-1289). Fixed: middleware.md rule 11 rewritten to enumerate all four internally generated responses (NotFound, MethodNotAllowed, OPTIONS auto-response, TSR/fixed-path redirect) that Use middleware wraps, and to state the shared "dynamic binding" rule (rebuilt against whatever `Use` chain is current when the cache was last invalidated, NOT fixed at `Handle()` time like ordinary routes). error-handling.md rules 5 and 10 rewritten to match; a new rule 21 added to error-handling.md §4 (GlobalOPTIONS Handler) making the OPTIONS case explicit (renumbered rules 21→39 down by one after the insertion point — safe, confirmed no other file references error-handling.md rule numbers, only section numbers). Cross-check: configuration.md rule 41 already correctly said these three handlers are "internally cached, middleware-wrapped" — that passage was already accurate and needed no change; it corroborates this fix.
2. **Header value slice sharing / aliasing guarantee (task item 10).** User decided: add as design principle 6 in README.md's "Design Principles" section (a natural home that exists but wasn't considered in the first pass — it fits better there than scattered per-file notes). Added: "Per-request header isolation" — every response header value the router/middleware writes belongs to that one request, never a slice shared or mutated across requests, even when a perf optimization writes directly into `w.Header()` instead of calling `Header.Set`.
