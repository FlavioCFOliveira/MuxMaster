Key verdicts from http-protocol-security-auditor scope:

**H-034 / CC-C (HandleFast TSR/405/OPTIONS/404 middleware bypass) — REFUTED**
HandleFast routes share the same lazyNotFound/lazyMethodNotAllowed/lazyOPTIONS fallback paths as Handle routes. These all call wrapMiddleware(…, m.middleware). No bypass possible. Confirmed by 13 tests in harness/fastpath_headers_parity_test.go with evidence showing mw_calls=1 on all fallback paths.

**H-033 (JWT alg:none) — REFUTED**
allowedAlgs map exact match prevents none/None/NONE/nOnE from ever being accepted. The middleware panics at construction time if Algorithms is empty, so there is no zero-configuration attack surface.

**H-032 (JWT algorithm confusion HS256-on-RS256) — REFUTED**
Algorithm allowlist check at parseAndValidateJWT line 266 rejects tokens whose alg field does not exactly match the configured algorithm list. Cross-algorithm tokens are rejected before signature verification.

**H-037 (OAuth2 SSRF via token in URL) — REFUTED**
Token is sent via url.Values POST body (percent-encoded). Endpoint URL is a fixed configuration string. Token bytes cannot reach the URL.

**H-044 (OAuth2 fail-open on introspection error) — REFUTED**
Both client.Do() network errors and non-200 HTTP responses from introspection endpoint produce 401. Confirmed: connection-refused → 401, 500 → 401.

**CC-B (CRLF+SSRF in OAuth2) — REFUTED**
CRLF bytes in token are percent-encoded by url.Values.Encode(). Protocol-relative token //evil.com/... does not alter introspection URL.

**Why:** Document for future sprints that HandleFast fallback paths are NOT a bypass risk because they all route through dispatch() which uses the same lazy handler infrastructure as the slow path. This was the sprint's highest-priority hypothesis (CC-C) and it was cleanly refuted.

**How to apply:** When future code changes modify lazyNotFound/lazyMethodNotAllowed/lazyOPTIONS, re-run TestFastAuthMiddlewareBlocksFallbacks and TestFast*Parity tests to confirm parity is maintained.
